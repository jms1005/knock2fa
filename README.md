# knock2fa — 버튼 시퀀스 + 노크 리듬 이중 인증 잠금 시스템

2026 COSS 차세대반도체 MCU 응용 경진대회 출품용 펌웨어.
ATmega328P / Microchip Studio / Bare-Metal (Arduino IDE·라이브러리 미사용).

---

## 1. 무엇을 하는가

| 단계 | 인증 요소 | 물리 채널 | 판정 |
|---|---|---|---|
| 1 | **지식** — 등록된 버튼 4개를 정해진 순서로 | 디지털 GPIO (PD2~PD5) | 순서 일치 |
| 2 | **행동** — 표면을 두드리는 리듬 | 아날로그 비교기 + ADC (PD7 / PC0) | 최근접 중심점 거리 |

두 단계는 서로 다른 주변장치에서 **독립적으로** 얻어지며,
**두 결과가 같은 사용자를 가리켜야만** 잠금이 풀린다.
순서만 알아내도, 리듬만 흉내내도 통과하지 못한다.

## 2. 왜 이 구조인가 (설계 근거)

### 2.1 시각은 하드웨어 캡처로, 진폭은 ADC로

노크 시각을 ADC 폴링으로 잡으면 샘플링 주기만큼 양자화되고 인터럽트 지연이
측정값에 섞인다. 리듬 인증은 **간격의 재현성이 전부**이므로 이 지터를 없애야 한다.

그래서 아날로그 비교기 출력을 `ACIC=1` 로 **Timer1 Input Capture** 에 직결했다.
ICR1 래치가 하드웨어에서 일어나므로 ISR 이 늦게 실행되어도 기록된 시각은
흔들리지 않는다. 분해능은 프리스케일러 /8 기준 **500 ns** 다.

진폭은 별개로 ADC 가 잰다. **비교기와 ADC 를 동시에 쓰려면 `ACME=0` 이어야
하므로**(ACME 방식은 `ADEN=0`, 즉 ADC 를 꺼야 동작한다), 피에조 노드에서 선을
두 가닥 뽑아 PD7(AIN1)과 PC0(ADC0)에 각각 연결한다. 두 주변장치가 같은 신호를
독립적으로 본다.

### 2.2 템포 정규화 — 이게 없으면 본인도 못 연다

간격을 절대 시간 그대로 비교하면, 같은 리듬을 조금 빠르게 치는 것만으로 모든
성분이 함께 줄어 거리가 급격히 커진다. 그래서 간격을 **총 연주 길이로 나눈
비율 벡터**로 바꾼다.

```
원본  [200ms, 400ms, 200ms]  ->  [250, 500, 250]
1.5배 [300ms, 600ms, 300ms]  ->  [250, 500, 250]   (동일)
```

전 구간 32비트 정수 연산이라 부동소수점 라이브러리(1.5~3 KB Flash)가 링크되지
않는다. 이 덕분에 판정은 기존 PEDD 프로젝트의 `classify_match()` 를
**한 줄도 고치지 않고** 재사용한다.

### 2.3 링잉 불응기

압전 디스크와 부착면은 한 번의 타격에 수 ms 동안 공진한다. 이 잔향을 걸러내지
않으면 노크 1회가 이벤트 3~5회로 잡혀 간격 벡터가 통째로 무너진다.
첫 검출 후 **50 ms** 동안의 추가 에지는 같은 노크로 보고 버린다
(`knock.c` 의 `BLANK_TICKS`, 실험 1에서 확정).

하드웨어 쪽에서도 `ICNC1=1` 로 입력 캡처 노이즈 캔슬러를 켜 두었다.
4개 표본이 연속으로 같을 때만 에지로 인정하므로, 문턱 근처에서 비교기 출력이
채터링하는 것을 걸러준다. 4클럭(250 ns)의 고정 지연이 생기지만 모든 노크에
동일하게 적용되므로 간격에는 영향이 없다.

### 2.4 임계값을 손으로 정하지 않는다

등록 시 같은 리듬을 5회 반복 입력받아, 표본들이 중심점에서 벗어난
**최대 제곱거리 × 2** 를 임계값으로 삼는다. 리듬이 일정한 사람은 좁게,
들쭉날쭉한 사람은 넓게 잡힌다. 흩어짐이 상한(20,000)을 넘으면 **등록을 거부**한다.
무리하게 넓혀 저장하면 타인도 함께 통과하기 때문이다.

### 2.5 전원을 뽑아도 실패 카운터는 지워지지 않는다

카운터가 RAM 에만 있으면 공격자는 몇 번 틀릴 때마다 전원을 뽑아 무제한으로
시도할 수 있다. 그래서 EEPROM 에 두고, 더 중요하게는 **시도를 평가하기 전에
먼저 증가**시킨다. 평가 후에 올리면 결과가 확정되기 직전에 전원을 끊어 회피할
수 있다.

카운터 자체가 기록 중 전원 차단으로 깨질 수 있으므로 값과 보수를 함께 저장해
무결성을 확인하고, 깨져 있으면 **최대 실패로 간주해 잠근다**(fail-closed).
5회 실패 시 30초 강제 대기이며, 대기를 다 채워야 카운터가 0으로 돌아간다.
잠금이 영구적이지 않으므로 장치가 벽돌이 되지 않는다.

### 2.6 재등록은 인증 성공 직후에만

대기 화면에서 아무나 길게 눌러 등록을 덮어쓸 수 있으면 잠금장치의 의미가 없다.
등록된 사용자가 하나도 없을 때(최초 설치)만 예외로 허용한다.

## 3. 배선

### 3.1 핀 배정 — 총 10핀

| 핀 | Uno | 연결 | 방향 | 비고 |
|---|---|---|---|---|
| PD2~PD5 | D2~D5 | 택트 스위치 4개 | 입력(내부 풀업) | 외부 저항 없음 |
| PD7 | D7 | 피에조 (+) | AIN1 (비교기 음극) | **변경 불가** |
| PC0 | A0 | 피에조 (+) 같은 노드 | ADC0 | 진폭 측정 |
| PC4 / PC5 | A4 / A5 | OLED SDA / SCL | I²C | |
| PB1 | D9 | 액추에이터 / 상태 LED | 출력 | 해제 시 HIGH |
| PD1 | D1 | UART TX 38400 8N1 | 출력 | 보드 USB 단자 |

### 3.2 피에조 입력 회로

```
   피에조(+) ──┬── 1MΩ ── GND        블리드 저항: 전하 누적 방지, DC 0V 바이어스
               │
               ├── 1kΩ ──┬── PD7 (AIN1)   비교기 음극 입력 = 시각
               │          └── PC0 (ADC0)   ADC 입력       = 진폭
               │
               ├── 1N4148 ── GND    (캐소드→피에조, 애노드→GND) 음의 스윙 클램프
               └── 1N4148 ── VCC    (애노드→피에조, 캐소드→VCC) 과전압 클램프
   피에조(−) ──────────── GND
```

- **1MΩ 블리드 저항이 없으면** 압전 전하가 빠지지 못해 노드 전위가 표류하고,
  두 번째 노크부터 문턱을 못 넘거나 계속 넘은 상태가 된다. **반드시 넣을 것.**
- 1kΩ 직렬 저항이 MCU 내부 ESD 클램프로 흐르는 전류를 제한한다.
  타격이 셀 수 있으므로 외부 1N4148 2개를 추가로 두는 쪽을 권한다.
- 문턱은 내부 1.1 V 밴드갭으로 고정된다. **감도 조절은 소프트웨어 진폭 게이트**
  (`knock.c` 의 `AMP_MIN`, 기본 70 ≈ 1.37 V)로 한다. 가변저항이 필요 없다.

## 4. 조작

| 상태 | 조작 | 결과 |
|---|---|---|
| 대기 (미등록) | KEY1 2초 길게 | 등록 시작 |
| 대기 (등록됨) | 아무 키 짧게 | 순서 입력 시작 |
| 순서 입력 | 키 4번 | 리듬 입력으로 진행 |
| 리듬 입력 | 4번 두드림 | 판정 |
| 해제됨 | KEY1 2초 길게 | 재등록 (다음 사용자 슬롯) |
| 해제됨 | 3초 경과 | 자동 잠금 |

- 등록은 순서 4자리 → 같은 리듬 5회 반복.
- 순서 입력 도중 10초간 입력이 없으면 취소된다.
- 리듬 입력에서 6초간 첫 노크가 없으면 취소된다.
- 5회 연속 실패 시 30초 잠금. **전원을 껐다 켜도 대기 시간은 유지된다.**

| `knockfp.c/h` | 신규 | 템포 정규화 지문. 하드웨어 비의존 |

**이 조건을 깨뜨리면 단위 테스트가 빌드되지 않는다.**

## 6. 빌드와 검증

### 6.1 Microchip Studio

`firmware/KNOCK2FA.atsln` 을 열고 F7. 설정(F_CPU, 헤더 경로 `../../common`,
-Os, PackStructureMembers, AllocateBytesNeededForEnum)은 이미 들어 있다.

### 6.2 명령줄 검증 (Studio 없이)

```sh
sh tools/build_check.sh   # -Wall -Wextra -Werror 로 전체 빌드 + 메모리 사용량
sh tools/run_tests.sh     # avr-gdb 시뮬레이터에서 단위 테스트 실행
```

`build_check.sh` 는 경고를 오류로 승격시킨다. 경고가 하나라도 남으면 실패한다.

> 한글 출력이 깨지면 터미널 코드페이지 문제다. `chcp 65001` 후 다시 실행하거나
> `build/test_result.txt` 를 UTF-8 로 열어 보면 된다.

```sh
sh tools/render_figures.sh        # 회로도·블록도·흐름도·브레드보드도 SVG -> PNG

python tools/make_ppt.py          # 발표자료 초안 (22장)

```

파싱으로 검증하므로, 텍스트에 `<` 같은 문자가 섞여 SVG 가 깨진 채로 PDF·PPT
에 실려 나가는 사고를 막는다.

### 6.4 메모리 사용량 (2026-09-10 실측)

```
.text  8972 B   .data  0 B   .bss  118 B
Flash  8972 / 32768 B  (27.4 %)
SRAM    118 /  2048 B  ( 5.8 %)
```

EEPROM 사용량은 44 바이트 (등록 정보 42 + 실패 카운터 2) / 1024 바이트.
등록 정보가 4바이트 늘어난 것은 인증 임계값을 사용자별로 저장하도록
바꿨기 때문이다(아래 8절 참고).

### 7.2 신규 구매

| 품목 | 사양 | 수량 | 용도 |
|---|---|---|---|
| 피에조 진동 센서 | 압전 디스크 | 2 (본체+예비) | 노크 검출 |
| 저항 | 1 MΩ | 2 | **블리드 저항 (필수)** |
| 저항 | 1 kΩ | 2 | 직렬 보호 |
| 다이오드 | 1N4148 | 4 | 입력 클램프 |

> 단가는 실제 구매 영수증 기준으로 확정해 보고서 부품 가격표에 넣을 것.
> 요강 3-라(경제성)는 **시스템 전체 부품 원가**를 보므로, 기보유품도 시장가로
> 함께 적어야 한다. 개발보드 대신 ATmega328P 단품 + 내부 8 MHz RC 구성으로
> 가면 크리스탈·보드가 빠져 총원가가 더 내려가고, 요강 2-가-3의
> "직접 제작한 Custom 보드" 가산도 노릴 수 있다.

| 미등록 슬롯 오인 매칭 | 시뮬레이터 실행 | 구조적으로 불가함 확인 |
| 회로도 배치 | Chrome 렌더링 후 육안 검토 | 라벨·배선 겹침 6건 수정 |
| 회로도 PDF | 페이지 수·MediaBox 파싱 | A3 가로 1페이지 (1191×842 pt) |
| 발표자료 22장 | PowerPoint 로 PNG 내보내 육안 검토 | 표·상자 겹침 2건 수정 |

### 확인되지 않은 것 (실물 없이는 불가능)

1. **비교기 에지 방향** — 평상시 `ACO=1`, 노크 시 `0` 으로 떨어진다는 전제로
   `ICES1=0`(하강 에지)을 썼다. 데이터시트상 맞지만, **실물에서 노크가 전혀
   잡히지 않으면 가장 먼저 `ICES1` 을 뒤집어 볼 것.**
2. **불응기 50 ms** — 피에조와 부착면의 공진 특성에 달렸다. 실험 1에서
   UART 로그를 보며 확정한다. 노크 1회가 여러 번 잡히면 늘리고,
   빠른 연타가 씹히면 줄인다.
3. **진폭 게이트 70** — 표면 재질과 타격 세기에 좌우된다. 실험 1에서 확정.
4. **ADC 프리스케일러 /16 (1 MHz)** — 데이터시트가 10비트 정확도를 보장하는
   50~200 kHz 범위를 넘는다. 여기서 필요한 것은 절대 정확도가 아니라 상대
   비교이고, 변환 1회를 13 µs 로 줄여야 수 kHz 로 공진하는 포락선의 최대치를
   잡을 수 있어서 의도적으로 선택했다. 진폭이 불안정하면 /32 로 낮출 것.
5. **임계값 상한 20,000** — 실험 3(재현성)·실험 4(타인 모사)의 FRR/FAR 곡선을
   보고 확정한다. 지금 값은 출발점이다.
6. **OLED I²C 주소** — 모듈에 따라 0x3D 인 제품이 있다 (`ssd1306.h`).

### 개발 중 테스트가 잡아낸 결함 (수정 완료)

- 임계값 상한이 60,000 이었을 때, (250,500,250) 과 (333,333,333) 처럼 **명백히
  다른 리듬의 제곱거리(41,667)가 상한 안에 들어와 통과**했다. 20,000 으로 낮추고
  회귀 테스트를 추가했다.
- 공장 출하 EEPROM(전 바이트 0xFF)이 "카운터 손상"으로 판정되어 **새 칩을 처음
  켤 때마다 30초 잠금 화면**부터 나왔다. 0xFF/0xFF 를 미사용 상태로 구분했다.
- 캡처 시작 직후 50 ms 동안 첫 노크가 통째로 무시되는 사각지대가 있었다.
  불응기 기준을 "한 불응기 전"으로 잡아 제거했다.
- `knock_init()` 이 `sei()` 이전에 불리는데 밴드갭 안정화 대기가 32비트 시각에
  의존해, 인터럽트가 꺼진 상태에서 오동작할 여지가 있었다. 16비트 모듈러
  뺄셈으로 바꿔 인터럽트 상태와 무관하게 만들었다.
- 등록 중 규칙에 맞지 않는 리듬을 계속 입력하면 등록 화면에서 빠져나오지
  못했다. 연속 5회 실패 시 취소되도록 했다.
- 인증 임계값(`threshold_d2`)이 `auth_db_t` 하나에 스칼라 하나로 저장되어
  **전 사용자가 공유**하고 있었다. 두 번째·세 번째 사용자를 등록할 때마다
  그 사람의 재현성만으로 임계값 전체가 덮어써져, 먼저 등록된 사용자의
  FRR/FAR 이 나중에 등록되는 사람에 따라 흔들리는 결함이었다. `threshold_d2`
  를 `centroid` 와 같은 `[AUTH_USERS]` 배열로 바꾸고, `run_auth()` 에서 지식
  인증(PIN)으로 확정한 사용자 번호에 맞는 값만 `classify_match()` 에 넘기도록
  고쳤다. EEPROM 배치도 함께 넓혔다(38→42바이트, 6절 참고).

## 9. 브링업 순서 (한 번에 다 연결하지 말 것)

1. **보드만** — 빌드·업로드 확인. OLED 없이도 UART 헤더가 나와야 한다.
2. **버튼 4개** — 순서 입력 화면에서 `*` 가 4개까지 찍히는지.
3. **OLED** — 화면 전환 확인. 안 되면 주소 0x3D 시도.
4. **피에조** — 블리드 저항부터 넣고, 진행 표시 `*` 가 노크마다 하나씩 늘어나는지.
   **한 번 쳤는데 여러 개가 찍히면 불응기를 늘린다.**
5. **등록 → 인증** 전체 흐름.
6. **액추에이터** — LED 로 먼저, 서보는 마지막에 (전류 소모로 리셋될 수 있다).

UART 로그(38400 8N1)는 OLED 가 죽어도 계속 나온다. 실험 데이터는 여기서 받는다.

```
seq,mode,pin_user,knock_user,d2,thr,n0,n1,n2,g0ms,g1ms,g2ms,a0,a1,a2,a3,result
0,ENROLL,0,,0,0,250,500,250,201,398,203,143,151,138,147,SAMPLE
5,AUTH,0,0,1204,6800,248,503,249,205,404,199,140,155,141,149,GRANT
6,AUTH,0,,38210,6800,331,334,335,266,268,271,132,140,135,144,DENY
```

판정이 미상일 때(`knock_user`)는 -1 대신 빈 칸으로 둔다. pandas 등에서 결측으로
읽히므로 통계 처리가 편하다.

실험 4(타인 모사)의 FAR 은 이 로그의 `result` 열을 세면 그대로 나온다.
